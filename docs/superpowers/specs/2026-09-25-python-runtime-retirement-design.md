# Python 运行时退役设计

## 目标

只有在 .NET 桌面实现已通过明确的合成回归测试、覆盖所有仍支持的可观察行为后，才退役旧版 Python 桌面运行时及其专属测试。整个迁移过程中，桌面发布包始终不包含 Python runtime。

## 已确认的决策

- 优先保持用户可观察到的正确性、安全性、失败处理、顺序和归档行为，不要求照搬 Python 的内部实现细节。
- 保留显式代理 URL 恢复能力，并维持与旧实现相同的公网目标校验保障。
- 真值数据构建、严格真值审计、批次验证、产物验证和模型校准作为独立的 Python 维护工具保留；其 Python 实现和必要测试不纳入桌面运行时删除范围。
- 在 .NET 合同和保留的 Python 工具测试分别通过验收前，不删除桌面 Python 模块或测试。

## Parity 项处置

| 尚未关闭的领域 | 处置方式 | 删除 Python runtime 前必须具备的证据 |
| :--- | :--- | :--- |

| 进度、有界日志与终态事件顺序 | 保留进度单调递增，并保证终态完成事件为最后一个事件。 | 使用确定性的 barrier/sink 测试证明终态返回后不会再提交进度或 trace 事件。 |

| 归档、人工复核、保留、重复项与恢复 | 保留终态、路径安全、回滚/恢复，以及提交失败时产物哈希不变量。 | 扩展现有恢复矩阵，增加提交失败后的哈希和状态断言。 |

已验证的五个 parity 领域继续由现有 .NET fixture/test 覆盖。Parity 矩阵必须区分 `verified`、`approved retired` 和 `out of desktop scope`；移除桌面 Python runtime 时，不得遗留 `partial` 或 `decision needed` 项。

## 工具边界

真值数据和审计工具链继续独立运行并接受测试。实施期间须先盘点其导入关系，避免随桌面代码误删共享依赖。运行时当前通过动态导入调用审计 hook；应将该调用关系与保留的审计工具合同拆开：在等效的 .NET 桌面覆盖完成后，只移除运行时耦合，保留工具 CLI 和不含敏感信息的输出行为。保留工具测试作为本地退役门禁运行，不进入 Windows CI；Windows CI 只运行 .NET job。

保留工具测试必须继续在本地独立于桌面 runtime 执行，并使用仓库声明的兼容 Python/pytest 版本。Windows CI 不安装 Python、不运行 pytest，仅验证 .NET 构建、测试和发布包。不得把真值数据、邮箱内容、凭据或签名 URL 加入共享 fixture。

## 实施顺序

1. 分别梳理桌面 runtime、真值工具和测试依赖的 Python 导入关系；编辑前先识别共享模块。
2. 为上述每项 parity 处置新增或扩展合成 fixture 与 .NET 定向测试；按需补齐 .NET 行为。
3. 更新 parity 矩阵，附上验证证据，并明确记录已批准退役或范围外的项目。
4. 固定保留 Python 工具的本地测试白名单及兼容依赖环境；Windows CI 保持 .NET-only，不增加 Python job。
5. 只删除已无工具/测试消费者的 Python 桌面运行时模块和专属测试；保留工具模块、其依赖闭包及对应测试。
6. 本地运行保留 Python 工具测试白名单；运行完整 .NET 测试套件、发布包审计及全仓导入/引用检查；重新构建 Windows 发布目录并确认其中仍不包含 Python runtime。Windows CI 继续只运行 .NET job。

## 验收标准

- 每个 parity 领域都有通过的 .NET 定向测试，或有明确批准的退役/范围外说明。
- 桌面 Python runtime 和仅服务于它的测试已移除；保留的真值/审计工具仍可运行且有测试。
- 桌面构建和发布过程不调用也不打包 Python。
- 保留 Python 工具测试在兼容依赖环境中本地通过；Windows CI 只执行 .NET job。
- 保留用户已有改动；除非用户明确要求，否则不创建 Git commit。
