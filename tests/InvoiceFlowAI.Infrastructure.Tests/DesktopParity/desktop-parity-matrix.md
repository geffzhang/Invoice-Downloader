# Desktop Python-to-C# Parity Matrix

Status vocabulary:

- `verified`: the C# focused test asserts the same observable rule with synthetic data.
- `partial`: C# implementation/tests cover a related path, but one or more Python-observed edges remain unverified.
- `gap`: the C# implementation or event contract does not currently provide the behavior.
- `decision needed`: the behavior exists in Python and has not been approved as retired/unsupported.

No Python fixture data, real mailbox content, signed URL query, or credential is copied into this matrix. Provider hosts below are family identifiers only.

## Fixture Coverage

`Fixtures/DesktopParity/pairing.json` contains synthetic expected pair membership and ambiguity outcomes. It is consumed by `DesktopParityFixtureTests.Pairing_golden_fixtures_match_python_desktop_decisions`. `providers.json` contains eight synthetic provider URL-family/expected-field cases consumed by `Provider_golden_fixtures_match_detection_and_field_projection_without_echoing_source_content`; it contains no credentials or signed query strings. `provider-recovery.json` now drives Baiwang wrapper/same-source selection, Nuonuo transient detail retry plus XML/PDF capture, and retry/PDF selection for all six direct families. It is synthetic and has no credentials or real signed links; per-family format/conflict/redirect matrix cases remain open. `mailbox-order.json` asserts stable UID filtering/dedupe/order; `candidate-order.json` asserts mailbox candidate ordering and sequence; `extraction.json` and `xml-extraction.json` are consumed by fixture-driven XML parser tests, with the latter also projected by Python's truth-dataset parser; `classification.json` is shared by Python and C# tests for unknown purchaser disposition and strong railway evidence; `archive-routing.json` covers candidate status and provider failure-code routing; `archive-recovery.json` exercises final/temp/missing recovery outcomes; `direct-artifact-selection.json` defines the C# PDF/XML/OFD selection contract.

This matrix is an inventory checkpoint, not a claim of full parity. `partial`, `gap`, and `decision needed` rows remain open until covered by a focused C# test or an explicit retirement decision.
