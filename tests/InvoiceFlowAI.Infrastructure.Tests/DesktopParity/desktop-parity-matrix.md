The Python implementation and all Python tests were removed on 2026-09-26. The Python evidence column below records historical behavior sources only; it does not indicate a current source, dependency, or test gate.

Status vocabulary:

- `verified`: the C# focused test asserts the same observable rule with synthetic data.
- `partial`: C# implementation/tests cover a related path, but one or more Python-observed edges remain unverified.
- `gap`: the C# implementation or event contract does not currently provide the behavior.
- `decision needed`: the historical Python behavior has not been approved as retired or out of desktop scope.
- `approved retired`: the historical behavior was explicitly approved for retirement and has a documented replacement or removal boundary.
- `out of desktop scope`: the historical utility behavior is not part of the Avalonia desktop contract.

No Python fixture data, real mailbox content, signed URL query, or credential is copied into this matrix. Provider hosts below are family identifiers only.

## Fixture Coverage

`Fixtures/DesktopParity/pairing.json` contains synthetic expected pair membership and ambiguity outcomes and is consumed by `DesktopParityFixtureTests.Pairing_golden_fixtures_match_python_desktop_decisions`; the named method preserves its historical name. `providers.json` contains eight synthetic provider URL-family/expected-field cases consumed by `Provider_golden_fixtures_match_detection_and_field_projection_without_echoing_source_content`; it contains no credentials or signed query strings. `provider-recovery.json` drives Baiwang wrapper/same-source selection, Nuonuo transient detail retry plus XML/PDF capture, and retry/PDF selection for all six direct families; its Python consumers are historical and only C# consumers remain. The fixture is synthetic and has no credentials or real signed links. `mailbox-order.json` asserts stable UID filtering/dedupe/order; `candidate-order.json` asserts mailbox candidate ordering and sequence; `extraction.json` and `xml-extraction.json` are consumed by C# fixture-driven XML parser tests; `classification.json` is consumed by C# tests for unknown purchaser disposition and strong railway evidence; `archive-routing.json` covers candidate status and provider failure-code routing; `archive-recovery.json` exercises final/temp/missing recovery outcomes; `direct-artifact-selection.json` defines the C# PDF/XML/OFD selection contract.

This matrix is an inventory checkpoint, not a claim that Python code remains. Every current desktop behavior is `verified`, explicitly `approved retired`, or `out of desktop scope`; Python paths in the historical evidence column are provenance only and are no longer runnable.
